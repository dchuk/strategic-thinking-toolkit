# Anti-Patterns Catalog

Every named anti-pattern from *How to Be Strategic*, organized by phase. Use this catalog to diagnose failure modes in a strategic session or plan, find the corrective principle, and link to the relevant tool reference.

---

## Problem Framing

Strategic work fails in recognizable ways. A facilitator who can name the failure mode in real time — "that's a HiPPO Curse" or "we're being Data-holics" — can intervene before the session goes off the rails. This catalog collects every named anti-pattern from the book, groups them by the phase they corrupt, and pairs each with its corrective rule.

The anti-patterns below are not abstract mistakes. Each has named signals — things you can observe in a room — and a specific fix drawn from the book's tools and principles.

## Think Phase Anti-Patterns

These corrupt route selection before any tool is even deployed.

### Anti-Pattern 1: Single-Route Default
**Applying the same problem-solving approach to every problem regardless of its nature.**

A team that always starts with data collection (Submarine), always drafts credentials decks (Staircase), or always generates creative options (Helicopter) is not choosing a route — it is defaulting to a habit.

**Fix.** Diagnose each problem against the characteristics of all four routes before choosing a method. Ask: Is an expert answer already known? Is reliable data available? Is this a future-oriented strategic issue requiring proof?

**Signals.**
- Always starting projects with a comprehensive data-gathering phase regardless of context
- Always producing a workplan and credentials deck before examining the problem
- Always generating creative options without any subsequent data validation

_source: ch06 opening paragraphs_

---

### Anti-Pattern 2: HiPPO Curse (Blinding Blunder of Brilliance)
**In the Helicopter route, one early option appears much shinier than others — often because the most senior person in the room favours it — and the remaining project time is spent polishing that option rather than genuinely evaluating alternatives.**

**Fix.** Treat all early options as equally likely candidates for long enough to allow data or structured evaluation to disprove the less viable ones before committing.

**Signals.**
- A senior stakeholder enthusiastically endorses one option very early
- Alternative options are quickly dropped without analysis
- The team spends most of the project perfecting a single idea chosen in the first meeting

_source: ch06 §Helicopter of Creative Discovery_

> See also: **HiPPO Convergence** in the Again phase, which is the same authority dynamic applied to voting rather than idea selection.

---

### Anti-Pattern 3: Late-Answer Submarine
**Spending so much time in the input/issue space gathering data that an answer only emerges very late in the project, leaving no time for refinement.**

**Fix.** Combine Submarine analysis with an upfront Helicopter phase (i.e., use the Rollercoaster) so that early options are visible to stakeholders while detailed analysis is underway.

**Signals.**
- Unable to offer any draft recommendation when a new stakeholder arrives mid-project
- Entire project timeline dominated by data collection with solution construction crammed into the final days
- Team says "we're still gathering data" when asked for an early view

_source: ch06 §Submarine of Analytical Research_

---

### Anti-Pattern 4: Using Data to Generate Ideas (Instead of to Test Them)
**In strategic contexts, attempting to derive ideas from large datasets rather than generating ideas first and then using data to validate or eliminate them.**

This wastes scarce data on idea generation rather than the far more efficient task of idea elimination.

**Fix.** Generate ideas through creative (Helicopter-style) methods first, then expose them to available data in the Down phase to eliminate weak options.

**Signals.**
- Hours of random research trying to "discover" what the answer might be
- Treating the absence of a data-backed idea as a blocker rather than generating hypotheses independently

_source: ch06 §HOW TO ELIMINATE OPTIONS IN NO TIME ('DOWN')_

## Up Phase Anti-Patterns

### Pyramid Principle (Up Tool 1)

#### Anti-Pattern 5: Writing the Pyramid in Pencil on Paper
**Writing the pyramid on a fixed page causes you to become wedded to the first structure you produce, preventing easy restructuring.**

**Fix.** Use Post-its so you can chop and change, alter priorities, and bundle ideas more intelligently.

**Signals.**
- Reluctance to revise the structure
- First draft treated as final

_source: ch08 §Strategic Pyramid examples_

---

#### Anti-Pattern 6: Writing Conditions as Negative Statements or Questions
**Phrasing pyramid building blocks as questions ("Will all guests be there?") or negatives ("No guest will be missing") fuels anxiety and impedes logical decomposition.**

**Fix.** Rewrite as positive declarative statements: "All the guests are there and happy."

**Signals.**
- Building block phrased as a question
- Building block uses "no" or "not" as the operative word

_source: ch08 §'5. Use positive statements'_

---

#### Anti-Pattern 7: Adding a Fourth Post-it at a Level
**When a fourth condition is suggested, the temptation is to simply add a fourth Post-it ("no unforeseen circumstances"). This weakens the logical structure.**

Rule 3 from the Pyramid Principle is: **No fourth Post-it.** Write down the fourth idea, then re-cut the four into three by finding a regrouping that fits the new idea into an existing or restructured set of three.

**Signals.**
- A Post-it labelled "other" or "unforeseen circumstances"
- Four or more Post-its at the same level

_source: ch08 §'4. Gradually replace buzzwords by full sentences'_

---

#### Anti-Pattern 8: Leaving Post-its as Buzzwords
**Keeping building blocks as single buzzwords (e.g. "guests", "logistics") rather than replacing them with full sentences narrows interpretation and makes it harder to decompose to the next level.**

**Fix.** Gradually replace each buzzword with a full sentence that captures the complete condition, reconciling different contributors' perspectives in one statement.

**Signals.**
- Single-word or two-word Post-its in mid or lower pyramid levels
- Difficulty generating sub-conditions for a node

_source: ch08 §'4. Gradually replace buzzwords by full sentences'_

---

### Happy Line (Up Tool 2)

#### Anti-Pattern 9: Over-investing in Low-importance KPCs
**Spending resources to achieve high performance on criteria that customers rank as unimportant, resulting in wasted investment and under-investment in criteria that actually matter.**

**Fix.** Identify Top-zone Post-its (high performance, low importance), accept a reduced performance on those dimensions, and redirect freed resources towards Front-zone KPCs (high importance, low performance).

**Signals.**
- A supplier scores very high on a right-side KPC while scoring average or below on left-side KPCs
- Marketing budget concentrated on easy, less important product attributes
- A dot well above the horizontal part of the Happy Line on the right side of the graph

_source: ch09 §The Happy Line of customer satisfaction_

---

#### Anti-Pattern 10: Spending Too Long on the Diagnostic, Too Little on Ideas
**Teams commonly invest most of their session time perfecting the KPC list and Post-it positions while leaving insufficient time to generate and package ideas.**

**Fix.** Timebox the Post-it plotting phase to five to ten minutes and allocate fifty to fifty-five minutes to idea extraction and packaging.

**Signals.**
- Session runs out of time before the idea-generation phase begins
- Team debates the exact ordering of KPCs for more than ten minutes
- No ideas written in Boxes 1–4+ by the end of the session

_source: ch09 §Happy Line example (time allocation advice)_

---

#### Anti-Pattern 11: Clustering High-importance KPCs Together
**Combining two or more high-importance KPCs into a single Post-it reduces the granularity needed to spot meaningful trade-offs.**

**Fix.** Resist clustering at the top of the importance ranking. If any of the top four or five KPCs contain a sub-criterion independently important enough to make the top seven, spin it off as a separate Post-it.

**Signals.**
- Fewer than five Post-its remain after the ranking exercise
- A single Post-it label covers two clearly distinct customer concerns
- Trade-off ideas seem hard to articulate clearly

_source: ch09 §Happy Line in practice – Tip 1_

---

#### Anti-Pattern 12: Stopping at "Improve A" as an Idea
**The first idea people generate is often a vague statement such as "improve punctuality", which is not actionable. Stopping there misses the five or six specific mechanisms that would actually achieve the improvement.**

**Fix.** Treat "improve A" only as a starting point and push immediately for at least five or six specific, concrete ways to achieve that improvement.

**Signals.**
- All ideas in Box 1 are phrased as "improve X" or "increase Y" without specifying a mechanism
- Ideas cannot be directly acted upon by a team member

_source: ch09 §Happy Line in practice – Tip 3_

---

### Mutation Game (Up Tool 3)

#### Anti-Pattern 13: Relying Solely on Copying Competitors
**Using competitor imitation as the only source of business innovation limits you to the visible 10% of ideas that survived their iceberg of failure.**

**Fix.** Supplement competitor monitoring with demand-side inspiration (customer observation) and self-mutation via the Mutation Game to access a broader idea space.

**Signals.**
- No internal ideation process exists
- Innovation pipeline mirrors competitors' recent moves
- No customer-originated ideas in the pipeline

_source: ch10 opening paragraphs_

---

#### Anti-Pattern 14: Unconsciously Crafting Meaningful Sentences During Mutation Exploration
**When picking mutations by hand, people unconsciously craft meaningful sentences row by row, skewing selection away from truly random combinations and missing potentially breakthrough ideas.**

**Fix.** Use the app at www.strategic.how/mutation to properly randomise mutations, which is closer to true natural selection and usually leads to more significant breakthroughs.

**Signals.**
- All explored mutations look logical and incremental
- No surprising or puzzling mutations have been examined
- Team is gravitating toward comfortable combinations

_source: ch10 §Tip 4_

---

#### Anti-Pattern 15: Stopping Too Early in Mutation Exploration
**Individuals run out of steam after eight to ten ideas, missing the long tail of valuable mutations that emerge from exhaustive exploration.**

**Fix.** Play with four to six people and systematically go through around 50 mutations; the more mutations explored, the higher the probability that one proves useful.

**Signals.**
- Session ends after fewer than 10 ideas
- Only one or two people generating ideas
- Grid not fully traversed

_source: ch10 §Mutating Peter's Social Life_

## Down Phase Anti-Patterns

### Payoff Profiles (Down Tool 1)

#### Anti-Pattern 16: Reserve Big Bet
**Committing to a high-risk, high-cost initiative (big bet) while the strategic posture is merely to reserve the right to play — yielding maximum risk for minimal differentiated reward.**

20–30% of company initiatives typically fall into this trap.

**Fix.** Transform the initiative by moving it toward "options" (reduce investment stages), toward "adapt" (increase the benefit/reward), or both simultaneously. Use the glide path approach to engineer successive improved versions.

**Signals.**
- The initiative is expensive AND has a high probability of failure
- Even in the best-case scenario, the outcome is no different from what competitors already offer
- The initiative is plotted in the top-right corner of the Payoff Profiles Matrix

_source: ch12 §Destroy_

---

#### Anti-Pattern 17: Jumping Ahead with the First Version of an Idea
**Executing the initial conception of a strategic initiative without first engineering its payoff profile, nearly always resulting in a sub-optimal outcome.**

**Fix.** Apply the Payoff Profiles Matrix before committing resources; use the glide path to iterate from the starting position to a more favourable risk–reward combination.

**Signals.**
- No structured risk–reward assessment has been done before committing
- The team is "moving fast and breaking things" without strategic validation

_source: ch12 §Payoff Profiles exercise_

---

### Landscape Analysis (Down Tool 2)

#### Anti-Pattern 18: Big Data Hoarding
**Gathering huge datasets before knowing what questions to ask, then interrogating them badly afterwards.**

Leads to slow analysis, biased thinking from accumulated data, and findings delivered too late to be useful.

**Fix.** Adopt the "sharp data" approach: identify the five key data points first, determine which you already have, then gather only the missing ones as quickly as possible.

**Signals.**
- Team is collecting "everything we can think of" before framing questions
- Analysis is delayed waiting for a comprehensive dataset
- The dataset has grown large but the strategic question is still unresolved

_source: ch13 §'Five key data points'_

---

#### Anti-Pattern 19: Submarine Path of Analytical Research
**Crawling through dataset after dataset in sequence without surfacing to test ideas, delaying progress and consuming resources without proportionate insight gain.**

**Fix.** Start analysis with the data already at hand; identify and fill only the two or three truly missing data points rather than collecting comprehensive additional datasets.

**Signals.**
- Project is waiting for "one more" dataset before drawing conclusions
- Multiple rounds of data collection are planned sequentially

_source: ch13 §'Five key data points'_

---

#### Anti-Pattern 20: Gross-Margin-Only Resource Allocation
**Making resource allocation decisions based solely on gross margin, ignoring the hidden consumption of unallocated fixed costs (rent, call centres, etc.) by individual products or customers.**

**Fix.** Perform XLP analysis to compute GM1 and GM2 by progressively allocating the largest fixed cost categories using appropriate allocation keys, revealing true profitability.

**Signals.**
- Decisions to promote or expand a product line are based on gross margin alone
- Fixed costs are treated as overheads and not attributed to products/customers
- A high-GM product is consuming disproportionate floor space or support resources

_source: ch13 §'LINE PROFITABILITY'_

---

#### Anti-Pattern 21: Anecdotal Competitor Benchmarking
**Drawing strategic inspiration from competitors that happen to be prominent in internal anecdotes rather than from objectively successful competitors.**

**Fix.** Build a GPS Chart to identify the champions (above-average growth and profitability) and draw inspiration specifically from the most relevant champion, not from the most familiar competitor.

**Signals.**
- Competitor referenced is frequently discussed internally due to staff moves or PR
- No objective growth/profitability data is used to select the benchmark

_source: ch13 §'GPS CHART'_

---

#### Anti-Pattern 22: Broad Survey Design ("Everything We Can Think Of")
**Asking as many questions of as many respondents as possible, resulting in slow turnaround, diluted insight, and less convincing results for stakeholders.**

**Fix.** Apply the "sharp data" approach: reduce the survey to the single most critical question through iterative refinement, select the smallest number of most predictive respondents, and gather data within hours rather than days.

**Signals.**
- Survey instrument has many questions
- No process of iterative question refinement was performed
- Respondents were selected randomly or by convenience

_source: ch13 §'Landscape Analysis example' (store managers survey)_

---

### Lean Startup (Down Tool 3)

#### Anti-Pattern 23: Waiting Too Long Before Testing
**Businesses hesitate to test ideas through actions and wait too long before testing an idea, preventing them from failing fast.**

**Fix.** Work in short, incremental and iterative product development cycles; replace "plan, decide, launch" with "test, learn, roll-out".

**Signals.**
- Long pre-determined workplans before any customer contact
- Linear project timelines with a single launch date

_source: ch14 §Lean Startup in action_

---

#### Anti-Pattern 24: Experiments That Are Too Large
**Businesses design experiments that are not small enough, making failure too costly and preventing them from failing often.**

**Fix.** Design the smallest possible MVP that tests only the critical hypotheses; use the "tenth of the budget" forcing function to shrink experiment size.

**Signals.**
- High fixed-cost commitments before customer validation
- MVP requires buying or building dedicated infrastructure

_source: ch14 §Lean Startup in action_

---

#### Anti-Pattern 25: Testing to Learn (Indiscriminate Testing)
**Organisations translate "test and learn" into "test to learn", running experiments on outcomes that are already known or where the difference between outcomes is not meaningful — effectively just running polls.**

**Fix.** Reserve tests for situations where the outcome is genuinely unknown and the difference between outcomes is meaningful; otherwise acknowledge it as a poll and treat it accordingly.

**Signals.**
- Testing things with already-known outcomes
- Showing many logo colour variants to thousands of people to pick the most popular
- Testing undertaken mainly to satisfy internal politics

_source: ch14 §Test Your Critical Hypotheses on Paper First_

---

#### Anti-Pattern 26: Buying or Building the MVP
**Spending real cash to buy or build an MVP that will be discarded after the test regardless of outcome, wasting money on assets headed for the scrap heap.**

**Fix.** Source MVP components through borrowing, bartering, or begging — calling in favours from suppliers, distributors or partners in exchange for internal resources.

**Signals.**
- Capital expenditure approved for first MVP
- Dedicated infrastructure commissioned before first customer test

_source: ch14 §Create the MVP with Borrow, Barter and Beg, Rather than Buy or Build_

---

#### Anti-Pattern 27: Testing Without Hide-ability or Deniability
**Established companies run experiments at visible scale or in their home market without any reputation firewall, so that a failed test generates negative brand coverage.**

**Fix.** Test in out-of-the-way locations and partner with a company for whom the worst-case scenario would not damage their own brand, so that any failure can be absorbed or reframed.

**Signals.**
- First test run in the company's primary market
- Company branding prominently featured on a first-round MVP that could fail publicly

_source: ch14 §Invest in Hide-ability and Deniability_

## Push Phase Anti-Patterns

### Impactful Words (Push Tool 1)

#### Anti-Pattern 28: Defaulting to Your Own Preferred Channel
**A communicator presents information only through their own preferred representation system rather than adapting to the audience's preferred channels.**

Old-fashioned salespeople, for example, deliver long verbal explanations (auditory) regardless of whether the customer is visual, kinaesthetic, or digital.

**Fix.** Observe the vocabulary and behaviour of your audience to identify their preferred channel(s), then adapt your language, media, and interaction style to match those channels.

**Signals.**
- Using only slides for every audience
- Delivering only verbal pitches regardless of audience type
- Handing brochures to auditory customers who want to talk

_source: ch16 §NLP Language example (Audi showroom)_

---

#### Anti-Pattern 29: Narrow Convincing Repertoire
**Relying habitually on only three or four of the ten ways to convince, leaving entire categories of people unpersuaded because those people respond to different methods.**

**Fix.** Identify your least-used convincing methods, practise them by mimicking colleagues who use them naturally, and consciously deploy a wider range in persuasion situations.

**Signals.**
- Always defaulting to Reason as the primary persuasion tool
- Never using Inspire, Feel Good, or Favour in professional settings
- Finding certain colleagues impossible to convince

_source: ch16 §10 Ways to Convince_

---

#### Anti-Pattern 30: Multi-Page Executive Summary
**Writing an executive summary that spans two or three pages, forcing recipients to flip pages and losing their attention before the key message lands.**

**Fix.** Condense the summary to exactly one page formatted like a flyer: slogan, photo, short bios, three metrics, and 200–300 words with highlighted text.

**Signals.**
- Executive summary exceeds one page
- No visual hierarchy or highlights
- More than 300 words of body text

_source: ch16 §Impactful Words exercise: How to pitch a new venture?_

---

### Simple Numbers (Push Tool 2)

#### Anti-Pattern 31: Rear-View Mirror Management
**Driving a business using only financial statements (lagging indicators), analogous to driving a car using only the rear-view mirror: difficult and dangerous.**

**Fix.** Supplement financial metrics with leading indicators from the customer, business process, and learning & growth perspectives.

**Signals.**
- Scorecard contains only revenue, cost, and profit metrics
- No customer satisfaction measures exist
- No process or learning metrics tracked

_source: ch17 §Financial perspective_

---

#### Anti-Pattern 32: Dashboard Overload
**Measuring everything and creating dashboards with hundreds of measures; leads to paralysis and diluted focus.**

**Fix.** Apply the Russian doll model: keep each individual or function's scorecard simple, targeting approximately 12 metrics maximum with three per perspective.

**Signals.**
- Dashboard has more than approximately 12 metrics
- Everyone in the organisation shares one giant dashboard
- No clear owner for individual metrics

_source: ch17 §Russian dolls_

---

#### Anti-Pattern 33: Spreadsheet-First NPV
**Jumping directly into Excel to populate all NPV numbers before understanding the qualitative shape of each option's business performance, resulting in a technically precise model built on poorly understood assumptions.**

**Fix.** Use the Pocket NPV approach: sketch the visual shape of investment, cash flows, and terminal value for each option on paper, establish relative orders of magnitude, then anchor with real numbers only once the picture is complete.

**Signals.**
- Team opens Excel before any visual comparison exists
- No discussion of relative magnitude between options
- Assumptions are buried in cell formulas rather than stated explicitly

_source: ch17 §Pocket NPV visual approach_

---

#### Anti-Pattern 34: Single-Metric Focus
**Selecting only one metric (e.g., salary) leads to a narrow range of behaviours that may be sub-optimal for both individual and organisation.**

**Fix.** Select a blend of metrics across temporal horizons: present-management metrics, future-outcome metrics, and aspirational long-term metrics.

**Signals.**
- Only one KPI tracked for a role or initiative
- All metrics belong to the same temporal horizon
- No aspirational or behaviour-changing metric present

_source: ch17 §Philippa illustration_

---

#### Anti-Pattern 35: Stale Metrics
**Continuing to track metrics that have become redundant or easily met, rather than retiring them and promoting new ones relevant to the current stage of the business.**

**Fix.** Build a glide path into the scorecard design that pre-specifies which metrics will be promoted when current ones become obsolete.

**Signals.**
- Metrics unchanged since company founding
- All indicators permanently green
- Metrics no longer linked to current strategic challenges

_source: ch17 §Netflix illustration and §glide path_

---

### Compelling Story (Push Tool 3)

#### Anti-Pattern 36: Using "If" Language at the End of a Project
**Retaining hypothetical "if … then" framing when presenting at the end of a project, when facts are already available. This signals a lack of conviction and keeps the story in the credibility zone rather than the compelling zone.**

**Fix.** Replace all "if" Post-its with assertive, fact-based statements. Shift language from "if A then B" to "because A, therefore B".

**Signals.**
- Presentation contains the word "if" before key claims
- Conclusions are framed as conditional rather than declarative
- Audience is left uncertain whether the team actually has data

_source: ch18 opening paragraphs_

---

#### Anti-Pattern 37: Relying on a Single Human Anecdote
**Using only one individual's story as the human evidence for a recommendation, which risks invalidating the case if that individual turns out to be unrepresentative.**

**Fix.** Select two representative individuals whose stories together give a human face to the analysis without introducing contradictory variety.

**Signals.**
- Only one customer or employee quote in the presentation
- The entire qualitative argument rests on one person's experience

_source: ch18 §TWO HUMAN ANECDOTES_

---

#### Anti-Pattern 38: Using Three or More Human Anecdotes
**Including three or more individual stories introduces too much variety in views, diluting and fragmenting the core message.**

**Fix.** Trim to exactly two representative anecdotes that reinforce the same strategic direction.

**Signals.**
- Three or more customer/employee quotes in the presentation
- Audience is confused by divergent perspectives

_source: ch18 §TWO HUMAN ANECDOTES_

## Again Phase Anti-Patterns

These corrupt the habits and culture that make strategic thinking repeatable.

#### Anti-Pattern 39: Data-holic (Endless Analysis of Future Data)
**Attempting to solve complex strategic problems through the accumulation and brute-force analysis of future data, always feeling "just one day of analysis short" of the perfect solution.**

This never ends well because future data is too unstructured and unreliable.

**Fix.** Accept that the future cannot be analysed; it can only be created. Use structured thinking techniques (Pyramid Principle, Happy Line, Mutation Game) to generate possible futures first, then analyse them.

**Signals.**
- Repeatedly requesting more time or more data before committing to a direction
- Treating a future-oriented problem with the same analytical approach used for present/past problems
- Feeling that a strategic conclusion is always just one more analysis away

_source: ch21 §3 (The Future Can't Be Analysed; It Can Only Be Created)_

---

#### Anti-Pattern 40: Reality Distortion / Vision Without Execution
**Preferring to keep a cherished idea or plan alive rather than testing it against reality, relying instead on lobbying and force of personality to convince others.**

**Fix.** Use validation techniques (Payoff Profiles Matrix, Landscape Analysis, Lean Startup) to expose ideas to real data quickly and cheaply, converting ideas into genuine solutions.

**Signals.**
- Convincing others through personality rather than evidence
- Avoiding or delaying empirical testing of a plan
- Strong attachment to a vision despite lack of confirming data

_source: ch21 §6 (You Need Real Data to Have Real Solutions)_

---

#### Anti-Pattern 41: Premature Satisfaction (Coach A Internal Dialogue)
**After finding a first solution, the internal voice offers strong praise ("Well done, you're a star, call it a day"), causing the search for better options to stop too early.**

**Fix.** Adopt a Coach B internal dialogue: acknowledge the effort, then ask "What are two widely different solutions to this problem?" and remind yourself "The third solution is often the best."

**Signals.**
- Accepting the first idea generated without exploring alternatives
- Framing the problem as solved after a single option appears

_source: ch20 §Tip 1_

---

#### Anti-Pattern 42: Dejection / Self-Critical Block (Coach C Internal Dialogue)
**The internal voice is so harshly critical ("That's probably not the answer, it's too hard for you") that the problem-solver stops searching out of discouragement.**

**Fix.** Consciously shift to a Coach B internal dialogue; treat finding solutions as an Easter egg hunt with multiple eggs waiting to be discovered.

**Signals.**
- Quickly concluding "I can't solve this"
- Abandoning the search after the first failed attempt

_source: ch20 §Tip 1_

---

#### Anti-Pattern 43: HiPPO Convergence
**Convergence is achieved in ten seconds because the Highest Paid Person's Opinion (HiPPO) simply chooses and others assent, bypassing all other participants' input.**

**Fix.** Use dots-based silent voting so every participant's view is registered before any debate, preventing any single authority from short-circuiting the convergence process.

**Signals.**
- A single senior person announces the chosen option with no discussion
- Others around the table nod without voicing disagreement

_source: ch20 §Tip 4_

---

#### Anti-Pattern 44: Endless Collaborative Debate
**In organisations that try to be collaborative, selecting among options becomes an open discussion where participants with tiny differences of opinion debate at length, consuming disproportionate time on low-stakes distinctions.**

**Fix.** Vote first with sticky dots in silence, then debate only the issues where disagreement is material and the outcome differs meaningfully between options.

**Signals.**
- Two people debating the order of second vs. third ranked items for minutes
- Discussion time grossly disproportionate to the importance of the distinction

_source: ch20 §Tip 4_

---

#### Anti-Pattern 45: Sitting Down for Creative/Strategic Work
**Conducting Up phase idea-generation sessions while participants are seated, which suppresses right-brain intuitive and left-brain structured idea generation.**

**Fix.** Get participants to stand up (and use Post-its on a wall) for any divergent or creative strategic exercise.

**Signals.**
- Everyone seated around a table during a brainstorm or Up session
- Laptop-centric, heads-down work during a supposed idea-generation meeting

_source: ch20 §Tip 3_

---

#### Anti-Pattern 46: High-Revision-Cost Physical Support (Paper/Whiteboard)
**Capturing strategic work-in-progress on paper or whiteboard creates a psychological cost to revision, causing facilitators to push back against marginal but valid suggestions and reducing the quality of the final output.**

**Fix.** Use Post-its on a wall or window so any suggestion that represents an improvement can be incorporated in seconds with zero friction.

**Signals.**
- Facilitator resisting a team suggestion because "it would mean redrawing the whole thing"
- Scratch marks and corrections making a paper draft look messy, discouraging further changes

_source: ch20 §Tip 3_

---

#### Anti-Pattern 47: Bike-shedding
**Groups devote extensive discussion time to trivial or familiar sub-issues while quickly rubber-stamping complex but unfamiliar strategic decisions, misallocating collective attention.**

**Fix.** Before a debate, explicitly name the relative importance of the issue; use dots voting to expose whether the group actually disagrees on the important matters, and redirect time accordingly.

**Signals.**
- Long heated debate over minor formatting or naming decisions
- A major strategic recommendation approved in two minutes while a trivial operational question consumes thirty

_source: ch20 §Tip 4_

## When to Use / When NOT to Use

**Use this catalog:**
- During session review: scan the signals column to name what just happened
- When briefing the strategy-reviewer agent before it evaluates a plan
- When preparing a Rollercoaster session to brief facilitators on the failure modes most likely in each phase
- When coaching a team member who keeps hitting the same wall

**Do NOT use this catalog as a checklist to apply all 47 items to every project.** The relevant anti-patterns depend on the route and phase in play. A pure Staircase project (expert execution) has almost no exposure to Up phase anti-patterns. A Submarine project has no Mutation Game risks. Use the Phase Map at the top of this file to scope which anti-patterns are live for your situation.

## Code Examples

The book uses Post-it metaphors and named signals as its primary diagnostic "code". The patterns below illustrate the before/after language shift the book prescribes.

**Pyramid Principle — positive vs. negative statement (Anti-Pattern 6):**

```
BEFORE (negative / question):
  "Will all guests be there?"
  "No guest will be missing"

AFTER (positive declarative):
  "All the guests are there and happy."
```

**Compelling Story — conviction language shift (Anti-Pattern 36):**

```
BEFORE (Clarity / Up phase language):
  "If our supply chain improves, then costs will fall."

AFTER (Conviction / Push phase language):
  "Because our supply chain has improved by 18%, costs have fallen by €2M."
```

**Payoff Profiles — glide path to escape the Reserve Big Bet (Anti-Pattern 16):**

```
Starting position:  Posture = Reserve  ×  Bet = Big Bet   → Destroy zone
Move 1:             Reduce investment staging             → Posture = Reserve  ×  Bet = Options
Move 2:             Increase upside benefit               → Posture = Adapt    ×  Bet = Options
Destination:        Posture = Adapt    ×  Bet = Options   → Discuss / Drag zone
```

**Lean Startup — borrow/barter/beg vs. buy/build (Anti-Patterns 24, 26):**

```
WRONG:  Approve capex → commission dedicated infrastructure → build MVP → test
RIGHT:  Identify critical hypothesis → borrow/barter/beg components
        → assemble cheapest possible MVP → test → learn → roll-out
```
